# 土壤样品送检配对

各站独立给土壤样品编送检号时会发生重号。合库后若直接按送检号取结论，就会串单。
这个 Flask 网页把送检单、主检结论、核定配对三种 CSV 分批存入 SQLite，并搜索一组
**包含送检号、加列最少**的等值联接键，使其恰好复现核定配对。只有用户确认并通过
复验后，才开放联接明细；补录破坏现用键时数据照收但明细停供，换键确认后恢复。

同一业务列在不同站可能叫不同名字（如「采样点」/「点位号」）：合库后两个名称先各占
一个备选列名额，数据员可在「合并备选列」页把两个已登记列并为一个保留名——逐行取
非空值，同行两个非空值不同则指出表名行号并退回整次合并。合并后两种名称共用一个
名额，补录时按入库时的列规则折算，找键与联接统一取合并值。

## CSV 格式

三份文件均为 UTF-8、逗号分隔、首行表头。

| 文件 | 必要列 | 其余列 |
| --- | --- | --- |
| 送检单 | `row_no`（唯一行号）、`sample_no`（送检号） | 0–8 个备选联接列 |
| 主检结论 | 同上 | 与送检单同名同集合 |
| 核定配对 | `submission_row_no`、`conclusion_row_no` | 无（恰好两列） |

- 行号在各自表内跨批次全局唯一；配对可引用任意历史批次的行号。
- 送检行与结论行各自最多被一条核定配对占用。
- 全库登记的备选列上限为 8 个（取多批列的并集，旧行没有的列为空值；
  已合并的别名不另占名额）。
- 允许只含表头的文件（便于只补一侧），但一批三份合计至少一行数据。
- 示例数据：`python scripts/make_demo_csvs.py samples`。

## 同义列合并（「采样点」/「点位号」）

不同站给同一业务列起了不同名字时，合库后两个名称会先各占一个备选列名额。
在「合并备选列」页选两个已登记列并指定保留名：

- **逐行取非空值**：每行从两列中取非空值作为合并值；同一行两个非空值不同，
  逐条指出表名（送检单/主检结论）和行号，**退回整次合并**，数据、列登记、
  供数状态均不变。
- **共用一个名额**：保留名留在登记中，旧名登记为别名（`column_aliases`），
  不再占用 8 个备选列名额；再次合并时别名会级联指向最新保留名。
- **原值留痕**：被改写行的原列名和原值存入 `original_values_json`，
  批次页可按行号查询。
- **键的处理**：全部联接键中的旧名换成保留名并去掉重复列；现用键按合并后的
  全库数据复验，仍恰好复现核定配对则继续供数，否则随合并停供，
  确认有效键后恢复。

补录按入库时的列规则折算：CSV 用了别名也算同一保留列（两侧文件用不同名称
同样接受）；同一行把两个名称都填了且值不同，按值冲突整批退回。找键与联接
明细统一取合并值。合并与补录都在单个写事务内完成，失败即整体回滚。

## 逻辑

**键的定义**：`sample_no` 必选，再加 0–8 个两侧同名的备选列。

**复验判据**（`joinlogic.evaluate`）：对每个键组统计两侧行数。

1. 每条核定配对两侧的行必须落在同一键组，否则记"漏连"；
2. 两侧都有行的键组必须恰好 1 送检 + 1 结论，且正是该核定配对，否则整组记"误连"。

判定只看组成员，不生成同键笛卡尔积。复杂度 O(行数 + 配对数) 每组键，搜索最多枚举
2^8 个子集，按加列数从 0 递增，第一个有解的层全部返回。

> 注意：有效性对列集合**不单调**。加列可能把一对核定配对按新列拆开，因此
> 全列键失败不代表无解，必须逐层枚举。实现与测试都覆盖了这一点。

**找键与无解诊断**：无解时页面列出

- 靠加列救不回来的配对（两侧送检号本身不同）；
- 最接近的键下仍漏连的送检行/结论行号；
- 仍误连的键组（多对多、一对一但非核定、一多争用），只报行号不展开。

**确认与供数**：

- 未确认键 -> `/detail` 返回 HTTP 423 并说明原因；
- 确认操作按**当前全库数据**重新复验，通过才写入启用键并恢复停供批次；
- 已失效的历史键也可在总览页"重新确认"，同样要过当前数据复验。

**补录使现用键失效**：整批数据在单个事务内入库后复验现用键。失效时把该键标记
`invalid`，供数事件记录原因，并把**本批**置为 `suspended`；既有批次不受影响。
明细停供直到确认新键。

**入库失败**：校验、行号冲突、配对引用/占用冲突、SQL 错误都会抛异常，
`write_transaction` 整体回滚，批次、行、配对、备选列登记、供数状态均保持原样。

## 自测

```bash
.venv/bin/python -m pytest -q          # 42 项单元/集成测试
# 端到端（需先启动一个指向全新库的服务）：
.venv/bin/python scripts/smoke_http.py http://127.0.0.1:8000
.venv/bin/python scripts/smoke_merge.py http://127.0.0.1:8000
```

`scripts/smoke_http.py` 会依次入库四批示例数据，覆盖：0 列键 → 复用送检号后
1 列键 → 同地块不同深度后 2 列键 → 完全重复行交叉配对的无解诊断；期间验证
串单停供、旧键复验拒绝、换键恢复、失败批次回滚与供数状态不变。

`scripts/smoke_merge.py` 覆盖同义列场景：异名两批各占名额 → 合并后共用一个
名额 → 键缩列引发误连停供 → 换键恢复 → 异名补录入库 → 补录同行两值冲突退回
→ 合并同行两值冲突退回。

## 尚未处理

- 用户认证与权限：任何能访问页面的人都能入库、合并列和确认键，适合内网单团队使用。
- 入库是同步请求；超大文件（>60 MB 会被拒绝）没有做后台任务化。
- 删除/更正已入库行的界面未提供，只能追加批次后再配对新键；因此合并时若某行
  两个名称的值冲突，只能先线下修正来源数据、重新入库后再合并。
- 送检号、备选列的空白值按空字符串参与等值比较，不做缺值特殊语义。
- CSV 的引号/换行按标准 RFC 4180 处理，不支持分隔符自定义。
- 旧库升级靠启动时的轻量迁移（行表补 `original_values_json` 列、新建
  `column_aliases` 表），没有引入版本化迁移工具。
